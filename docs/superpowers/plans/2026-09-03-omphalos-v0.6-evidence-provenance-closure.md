# Omphalos v0.6 Evidence / Provenance Closure Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close the canonical discovery-to-evidence chain by adding explicit VerifiedEvidence, claim-evidence relations, source-family provenance/independence, immutable persistence, and append-only closure events while preserving all existing retrieval/evidence boundaries.

**Architecture:** Keep current `materialize_acquired_assets()` and `materialize_candidate_evidence()` ownership. Add an evidence-closure layer that promotes only real `CandidateEvidence` after required verification dimensions pass, attaches source-family provenance, and permits claim support/contradiction relations only after explicit `SEMANTIC_SUPPORT` verification. Persist verification/verified-evidence/provenance/claim-relation records through an additive `EvidenceClosureStore` extension that shares the existing `TrustedDataStore` SQLite connection; extend `TrustedExecutionRuntime` only to persist the anchor verifications it already creates through that extension.

**Tech Stack:** Python 3.11+, dataclasses/StrEnum, existing Evidence/SourceGraph/TrustedDataStore contracts, SQLite additive schema migration, pytest.

**Spec:** `docs/papers/Omphalos_AUSI_Runtime_v1.0_Roadmap_Technical_Whitepaper_v0.1_2026-09-03.md` §11 (v0.6).

## Global Constraints

- `Retrieved != Verified`.
- `Citation != Support`.
- `QuoteMatch != SemanticSupport`.
- `ProviderGrounding != VerifiedEvidence`.
- `DiscoveryCandidate` and `ArtifactKind.CANDIDATE` remain discovery-only.
- LLM recall can never be promoted into external VerifiedEvidence.
- Anchor verification is not semantic claim verification.
- Claim SUPPORTS / CONTRADICTS / QUALIFIES requires explicit `VerificationDimension.SEMANTIC_SUPPORT` PASS tied to that claim/evidence.
- Source-family identity and independent-root count come from `SourceFamilyResolution`, never from raw citation/result count.
- `CITES` remains non-collapsing provenance.
- Evidence/verification history remains append-only/conflict-safe; no silent mutation of same evidence identity.
- UsageEnvelope / policy provenance travels into VerifiedEvidence.
- No new Provider, Search Method, Planner, stopping semantic, or crawler rewrite in v0.6.

### Task 2: Promotion gate — CandidateEvidence to VerifiedEvidence

**Files:**
- Create: `src/ai_web_research/evidence/closure.py`
- Test: `tests/ausi/test_evidence_promotion_gate.py`

**Interfaces:**
- `EvidencePromotionPolicy(policy_id, require_anchor=True, require_source_identity=True, require_fixity=False)`.
- `EvidencePromotionDecision(promotable, reason_codes, required_dimensions, passed_dimensions)`.
- `evaluate_evidence_promotion(candidate, verifications, policy)`.
- `promote_candidate_evidence(candidate, verifications, policy, created_at) -> VerifiedEvidence` or raises `EvidencePromotionRejected`.
- Default promotion requires:
  - CandidateEvidence instance;
  - source_type != `llm_recall`;
  - source identity when policy requires it;
  - anchor refs + ANCHOR PASS when required;
  - SOURCE_IDENTITY PASS when required;
  - optional FIXITY PASS;
  - no FAIL/REVIEW on required dimensions.
- Anchor PASS alone is explicitly insufficient when source identity is required.
- No SEMANTIC_SUPPORT requirement for evidence existence; semantic support is a separate claim-link gate.

### Task 3: Claim-link gate and source-family provenance

**Files:**
- Create: `src/ai_web_research/evidence/provenance.py`
- Create: `src/ai_web_research/evidence/claim_links.py`
- Test: `tests/ausi/test_evidence_provenance_claim_links.py`

**Interfaces:**
- `resolve_evidence_provenance(evidence, family_resolution, relations=()) -> EvidenceProvenance`.
- Unknown source-family mapping gets an explicit unresolved root ref; it does not fabricate independence.
- `link_evidence_to_claim(evidence, claim_id, relation_type, semantic_verification, provenance, created_at) -> ClaimEvidenceRelation`.
- Relation creation requires `SEMANTIC_SUPPORT` PASS and matching `claim_ref`; ANCHOR PASS cannot create a relation.
- `assess_claim_evidence(claim_id, relations, provenances, minimum_independent_support_roots=2) -> ClaimEvidenceAssessment`.
- Multiple mirrored/syndicated/derived sources in one family count as one independent root.
- Separate family roots count separately.
- Contradiction from any independent root makes assessment CONTESTED; >=2 independent support roots without contradiction may be CORROBORATED.

- [ ] Write RED tests for unresolved provenance, same-family dedupe, two-root corroboration, contradiction, and anchor-only claim-link rejection.
- [ ] Implement provenance bridge and claim-link assessment.

**Interfaces:**
- `EvidenceClosureRuntime(store)` records verification results, promotes candidate, attaches provenance, optionally links to claim, assesses claim evidence, and appends closure ledger events.
- New closure ledger events use append-only identities such as:

  - `EVIDENCE_PROMOTED`
  - `PROVENANCE_ATTACHED`
  - `CLAIM_EVIDENCE_LINKED`

- Extend `EvidenceGapType` additively for missing semantic support / unresolved provenance if required by E2E; do not weaken existing gap semantics.
- E2E proves:
  1. search/grounding DiscoveryCandidate is not promotable;
  2. fetched/extracted CandidateEvidence + quote/anchor PASS alone is not claim support;
  3. source identity + anchor verification promotes VerifiedEvidence;
  4. only SEMANTIC_SUPPORT PASS can create SUPPORTS/CONTRADICTS relation;
  5. mirrored sources collapse to one independent root;
  6. second independent source can produce CORROBORATED state;
  7. explicit contradiction produces CONTESTED state;
  8. UsageEnvelope ref and provenance survive persistence/reload;
  9. ledger is append-only and auditable.
