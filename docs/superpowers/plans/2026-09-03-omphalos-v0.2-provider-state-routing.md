# Omphalos v0.2 Provider State & Dynamic Routing Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build Omphalos v0.2 so one Search Method can deterministically select and substitute eligible Provider bindings from runtime ProviderState without changing Method identity, while preserving Policy authority and recording the routing decision in Search Receipt metadata.

**Architecture:** Add a focused `routing/` package containing dynamic provider/surface state, state snapshots, routing policy, deterministic binding selection, and sanitized routing decisions. Routing happens after a Search Method is chosen and before authorization/execution; it never grants permission. Search Receipt stores only a sanitized routing summary. The first pressure test uses the current `method.lexical_search@1.0.0` ecosystem: Gemini Vertex, Gemini AI Studio, Grok Web, and Brave.

**Tech Stack:** Python 3.11+, dataclasses, StrEnum, existing `SearchMethodRegistry`, `ProviderRegistrySnapshot`, `MethodBinding`, `ProviderTopology`, `SearchReceiptRecorder`, pytest/pytest-asyncio.

**Spec:** `Omphalos / AUSI Runtime v1.0 Roadmap Technical Whitepaper v0.1`, section `v0.2 — Provider State & Dynamic Routing` (canonical roadmap approved 2026-09-03).

## Global Constraints

- `Search Method != Provider != Surface != Adapter != Credential`.
- Routing selects a binding; it never authorizes execution.
- `UNKNOWN != ALLOW`; stale/unknown provider policy state cannot be silently converted to permission.
- Missing runtime ProviderState is ineligible by default; explicit policy can opt into unknown-state routing.
- Credentials are represented only as `credential_available: bool | None`; credential values must never enter ProviderState, RoutingDecision, Search Receipt, logs, tests, or release artifacts.
- Dynamic quota/cost/latency are ProviderState, not Search Method semantics.
- Same Search Method identity must survive provider substitution.
- Existing provider adapters and `src/crawler/*` are not rewritten in v0.2.
- Routing output must be deterministic for the same RegistrySnapshot + ProviderStateSnapshot + RoutingPolicy.

### Task 2: Deterministic BindingSelector

**Files:**
- Create: `src/ai_web_research/routing/selector.py`
- Modify: `src/ai_web_research/routing/models.py`
- Test: `tests/ausi/test_dynamic_routing.py`

**Interfaces:**
- `RoutingPolicy` contains hard limits and deterministic preference lists.
- `BindingSelector.select(method_ref, providers, states, policy) -> RoutingDecision`.
- `RoutingDecision.selected_binding_id` is the selected enabled binding.
- `RoutingDecision.candidates` records every considered binding and its eligibility/reason codes.

- [ ] **Step 1: Write failing selector tests**

Cover hard eligibility:

```text
binding disabled                 -> reject
missing ProviderState            -> reject by default
availability=UNAVAILABLE         -> reject
availability=DEGRADED            -> reject unless allow_degraded
credential_available=False       -> reject authenticated surface
credential_available=None        -> reject authenticated surface by default
model_available=False            -> reject
quota_remaining <= 0             -> reject
cost > max_estimated_cost        -> reject
latency > max_estimated_latency  -> reject
policy_freshness=STALE           -> reject when require_fresh_policy_state=True
```

Cover deterministic preference order:

```python
RoutingPolicy(
    preferred_binding_ids=(
        "binding.lexical_search.gemini_google_vertex.v1",
        "binding.lexical_search.gemini_google.v1",
        "binding.lexical_search.grok_web.v1",
        "binding.lexical_search.brave_search.v1",
    )
)
```

When multiple bindings are otherwise eligible, the first explicit preferred binding wins. Without explicit preference, fallback order is deterministic by availability class, estimated cost, estimated latency, provider id, surface id, binding id.

# v0.2 Acceptance Criteria

- [ ] PS-01 ProviderState is provider-version + surface specific.
- [ ] PS-02 ProviderState carries availability, health, credential presence, quota, cost, latency, policy freshness, runtime capabilities, model availability, and observation time.
- [ ] PS-03 ProviderState/Receipt never retain credential values.
- [ ] PS-04 BindingSelector only considers enabled bindings for the requested Method.
- [ ] PS-05 Hard state constraints reject unavailable/unauthenticated/exhausted/ineligible bindings.
- [ ] PS-06 Routing preference is explicit and deterministic.
- [ ] PS-07 Same Method survives provider substitution.
- [ ] PS-08 Routing never performs authorization and cannot turn UNKNOWN into ALLOW.
- [ ] PS-09 RoutingDecision is auditable and enters Search Receipt metadata.
- [ ] PS-10 Vertex Gemini → AI Studio Gemini → Grok Web → Brave substitution pressure test passes.
- [ ] PS-11 No `src/crawler/*` rewrite is introduced.
- [ ] PS-12 Fresh relevant suite + compileall pass before PR completion claim.

# Explicit Non-Goals for v0.2

- No learned routing policy.
- No autonomous planner rewrite; that is v0.4.
- No Search Method Corpus; that is v0.3.
- No new search provider unless required to repair an existing binding.
- No automatic billing API polling.
- No provider-specific quota scraping.
- No retry/backoff orchestration redesign.
- No PolicyEvaluator bypass or policy inference from prior successful executions.
- No Economic or Meteorological Domain Pack implementation.
