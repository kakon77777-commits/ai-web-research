# Omphalos v0.3 Search Method Corpus Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the first canonical Search Method Corpus, define the v1 Core Method Target, and measure MethodCoverage without pretending documented methods are executable.

**Architecture:** Keep `SearchMethodSpec` and `MethodAvailability` as runtime execution contracts. Add a separate corpus layer with `MethodLifecycle` for research/maturity state, immutable deterministic snapshots, curated core/domain entries, registry consistency validation, and a v1 core coverage report.

**Tech Stack:** Python 3.11+, dataclasses, enum/StrEnum, hashlib/json deterministic snapshots, pytest.

**Spec:** `docs/papers/Omphalos_AUSI_Runtime_v1.0_Roadmap_Technical_Whitepaper_v0.1_2026-09-03.md` §8 (v0.3).

## Global Constraints

- `MethodAvailability` answers runtime executability; `MethodLifecycle` answers corpus maturity. Never conflate them.
- No provider-branded method IDs.
- Documented-only methods MUST NOT be registered as executable `SearchMethodSpec` unless implementation exists.
- Domain methods remain domain-scoped and do not automatically satisfy the core method target.
- No new Provider, Planner, Policy, Evidence, or Domain implementation in this milestone.
- TDD: every production behavior begins with a failing test.
