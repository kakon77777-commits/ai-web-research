# Omphalos v0.5 Stopping / Coverage / Saturation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Formalize search stopping, coverage, saturation, uncertainty, and marginal-gain control so Omphalos can decide CONTINUE / REPLAN / STOP / REVIEW without equating no results with falsity or saturation with complete recall.

**Architecture:** Add a separate `stopping` control layer. Observable search progress and typed coverage/budget/uncertainty state feed a deterministic `StopEvaluator`; low marginal gain normally requests REPLAN, while hard limits, explicit review requirements, terminal coverage policy, no material gaps, or bounded saturation under satisfied coverage can terminate the epoch. A `SearchControlRuntime` gates v0.4 planning without changing planner, routing, or Policy authorization semantics.

**Tech Stack:** Python 3.11+, dataclasses/StrEnum, existing v0.4 autonomous planner, SearchReceipt metadata, pytest.

**Spec:** `docs/papers/Omphalos_AUSI_Runtime_v1.0_Roadmap_Technical_Whitepaper_v0.1_2026-09-03.md` §10 (v0.5).

## Global Constraints

- `NotFound != False`.
- `Saturation != CompleteRecall`.
- Low marginal gain alone MUST NOT imply completeness.
- Stopping MUST NOT grant Policy authorization or modify ProviderState.
- Search budget is a control boundary, not a planner hint.
- Coverage axes are explicit and independently measurable.
- Search Receipt stores observable stop/control facts only; no hidden reasoning or credentials.
- No new Provider or Search Method implementation in this milestone.
- v0.5 MUST NOT redesign v0.4 planner graph semantics.

### Task 3: Deterministic StopEvaluator

**Files:**
- Create: `src/ai_web_research/stopping/evaluator.py`
- Test: `tests/ausi/test_stop_evaluator.py`

**Interfaces:**
- `StopEvaluator.evaluate(context, policy) -> StopEvaluation`.
- Priority:
  1. human review;
  2. policy blocked;
  3. provider unavailable;
  4. time limit;
  5. action/cost budget exhaustion;
  6. no material gaps;
  7. terminal coverage policy;
  8. saturation only when required coverage is satisfied;
  9. low marginal gain => REPLAN, not STOP;
  10. otherwise CONTINUE.
- A no-result/not-found condition without another stop criterion returns CONTINUE/REPLAN and never a falsity conclusion.
- Saturation with unmet required coverage returns REPLAN, not STOP.

- [ ] Write RED tests for every canonical reason and precedence.

### Task 4: SearchControlRuntime planner gate + explicit stop plans

**Files:**
- Create: `src/ai_web_research/stopping/control.py`
- Test: `tests/ausi/test_search_control_runtime.py`

**Interfaces:**
- `ControlledPlanningResult(stop_evaluation, plan, planning_result)`.
- `SearchControlRuntime.plan_or_stop(...)`.
- STOP/REVIEW emits a one-node `SearchPlan` containing `StopNode`/`StopAction`.
- CONTINUE/REPLAN delegates to existing `AutonomousPlannerV1`; v0.4 planner source is not modified.
- Stop plan metadata records stop reason and typed coverage/saturation state.
- Control runtime never calls PolicyEvaluator and never marks authorization.
