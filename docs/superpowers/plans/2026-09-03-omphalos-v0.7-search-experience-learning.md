# Omphalos v0.7 Search Receipt / Experience Learning Implementation Plan

> **Execution mode:** TDD, inline execution, single milestone branch/commit.

**Goal:** Convert observable SearchReceipt history into deterministic Search Experience records, aggregate method/provider/gap/evidence/cost/latency metrics, and expose preference-only Planner Prior snapshots without granting authorization.

## Global constraints

- `SearchReceipt != ChainOfThought`.
- `Learning != SelfAuthorization`.
- Experience is derived from observable receipts/facts; it is not new ground truth.
- Policy DENY/UNKNOWN/REVIEW is not provider failure.
- Unknown yield is `None`, not zero.
- Planner Prior may reorder caller-supplied candidates only; it may not add an ineligible method/provider/binding.
- No credential values, hidden reasoning, arbitrary receipt metadata, or authorization objects may be persisted in Experience/Prior records.
- Existing SearchReceipt schema/store remain unchanged in v0.7.

### Task 1 — Experience contracts

**Create:** `src/ai_web_research/experience/models.py`  
**Test:** `tests/ausi/test_experience_models.py`

- `ExperienceOutcome`: SUCCESS / EMPTY / PARTIAL / FAILED / BLOCKED / REVIEW.
- `ExperienceYieldFact` binds observable yield to immutable `action_receipt_id`.
- `SearchExperienceRecord` stores method/provider/outcome/result/yield/cost/latency/gap signals plus receipt/fact provenance.
- Schema must contain no authorization, credential, or reasoning fields.

### Task 2 — Deterministic receipt derivation / dataset

**Create:** `src/ai_web_research/experience/dataset.py`  
**Test:** `tests/ausi/test_experience_derivation.py`

- Map SearchActionReceipt policy/observation state to ExperienceOutcome.
- Normalize cost only from explicit USD-denominated keys; counters such as requests/tokens are not summed as money.
- Do not copy arbitrary receipt metadata.
- Preserve unknown yield as `None`.
- Dataset ordering/hash must be deterministic.
- Reject duplicate receipt IDs and duplicate action-receipt IDs to prevent double counting.
- Version derivation as `0.7.0`.

### Task 3 — Metrics and Planner Prior

**Create:**
- `src/ai_web_research/experience/metrics.py`
- `src/ai_web_research/experience/prior.py`

**Test:** `tests/ausi/test_experience_metrics_prior.py`

Metrics include:

```text
MethodSuccess
ProviderSuccess by Method
Execution / Provider Failure Rate
Candidate Yield
Verified Evidence Yield
Independent Root Yield
GapResolution(method, gap_type)
Cost Efficiency
Latency Efficiency
```

Planner Prior:

- version `0.7.0`;
- task-class scoped;
- deterministic method/provider ranking;
- preference only;
- can only reorder caller-supplied candidates.

### Task 4 — Additive persistence / replay

**Create:** `src/ai_web_research/experience/store.py`  
**Test:** `tests/ausi/test_experience_store_replay.py`

Additive tables on the existing receipt-store SQLite connection:

```text
search_experience_records
experience_dataset_snapshots
planner_prior_snapshots
```

Same identity + same payload is idempotent. Same identity + changed payload raises `ExperienceStoreConflict`.

### Task 5 — Experience Learning Runtime E2E

**Create:** `src/ai_web_research/experience/runtime.py`  
**Test:** `tests/ausi/test_experience_learning_e2e.py`

`ExperienceLearningRuntime.learn(...)`:

```text
receipts + task contexts + observable yield facts
→ SearchExperienceDataset
→ persist records/snapshot
→ aggregate metrics
→ PlannerPriorSnapshot per task class
→ persist prior snapshots
```

E2E must prove:

1. successful provider outranks failed provider from observed history;
2. policy-blocked provider is not provider failure;
3. prior cannot reintroduce a provider omitted by eligibility/policy;
4. exact replay is idempotent and produces same dataset/prior IDs.
