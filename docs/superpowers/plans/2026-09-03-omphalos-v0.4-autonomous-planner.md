# Omphalos v0.4 Autonomous Search Planner v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a provider-neutral autonomous planning layer that proposes method-level search strategy, compiles only execution-ready methods through current ProviderState routing, emits valid bounded `SearchPlan` graphs, and keeps Runtime validation and Policy authorization authoritative.

**Architecture:** Separate `SearchStrategyProposal` from executable `SearchPlan`. A proposer names objectives and candidate Search Methods but never credentials/providers; `AutonomousPlannerV1` gates those methods against `MethodCorpusSnapshot` + `MethodRegistrySnapshot`, routes through v0.2 `BindingSelector`, compiles parallel/branch/provider-fallback/join/bounded-replan graph nodes, and emits only observable planning metadata. Existing `PlanValidator` remains the final structural/runtime contract gate; `PolicyEvaluator` remains outside planning and authoritative for execution.

**Tech Stack:** Python 3.11+, dataclasses/StrEnum, existing `planning.graph`, v0.2 `routing`, v0.3 method corpus, pytest.

**Spec:** `docs/papers/Omphalos_AUSI_Runtime_v1.0_Roadmap_Technical_Whitepaper_v0.1_2026-09-03.md` §9 (v0.4).

## Global Constraints

- `AI proposes -> Runtime validates -> Policy authorizes` is invariant.
- A proposal MUST NOT contain provider credentials, API keys, secret values, provider IDs, binding IDs, or raw provider-specific request bodies.
- `DOCUMENTED` methods are knowledge only; default planner may compile only `EXECUTABLE|VALIDATED` corpus methods whose runtime `SearchMethodSpec` is executable.
- `EXPERIMENTAL` methods require explicit `PlanningPolicy.allow_experimental=True` and runtime availability other than `UNAVAILABLE|DEPRECATED`.
- Provider selection MUST use v0.2 ProviderState routing; planner must not directly instantiate provider adapters.
- Routing is not authorization; no planner result may encode `ALLOW`.
- Planner metadata/receipts store observable method/objective/routing/budget facts only, never hidden reasoning or Chain-of-Thought.
- v0.4 MUST NOT add a new Provider or expand the seven documented-only v1 core methods merely to make planner tests pass.
- Generic arbitrary proposal-DAG dependencies are out of v0.4 scope; this milestone supports independent parallel proposal steps, provider fallback branch, join, and one bounded replan loop.

### Task 4: AutonomousPlannerV1 compiler

**Files:**
- Create: `src/ai_web_research/planning/autonomous.py`
- Test: `tests/ausi/test_autonomous_planner_v1.py`

**Interfaces:**
- `AutonomousPlannerV1.plan(task, state, methods, corpus, providers, provider_states, routing_policy, planning_policy, proposal=None) -> AutonomousPlanningResult`.
- If `proposal is None`, use `RuleProposalSource`.
- For each proposed step, choose the first candidate method that passes lifecycle + runtime availability + method registry + compatible input + eligible routing gates.
- `DOCUMENTED` methods cannot compile.
- `EXPERIMENTAL` methods compile only with explicit planning policy and executable runtime spec/binding.
- `enable_query_divergence=False` blocks that method even if proposed.
- Selected provider/binding comes only from `BindingSelector`.
- Provider fallback compiles `BranchNode(TRUE -> fallback, FALSE -> join)` using the same `method_ref`.
- Multiple independent proposal steps may become parallel entry actions and converge at one `JoinNode`, bounded by `max_parallel_branches`.
- If open gaps request replanning, compile one `LoopNode`; `max_iterations = min(budget.max_loop_iterations, proposal.max_replans + 1)`.
- Action-node count never exceeds `PlanningBudget.max_actions`.
- If no method can compile, return a `StopNode` plan with explicit `NO_EXECUTION_READY_METHOD` or `NO_ELIGIBLE_BINDING`.
- Result exposes `plan`, `proposal`, `decision_summary`; no hidden reasoning.
